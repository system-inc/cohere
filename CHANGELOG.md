# Changelog

Every release of cohere has a section here, newest first. Versions follow semver, as
[CONTRIBUTING.md](CONTRIBUTING.md#versioning-and-the-changelog) states. Each section lists, per rule
set, every rule turned on or off, every severity and option change, and every other setting that
changed. It's generated by `go run ./internal/release/tools/changelog` from the sets themselves. What
changed in cohere outside the sets is written under the same heading.

### Added

- A settings file's go block takes reasons, why each rule it turns off is off, in a sentence, as the TypeScript
  block's reasons say it. Coverage prints the reason beside the rule. In a root that governs a module of ours, one
  whose path is under github.com/system-inc/, an off with no reason is refused at load, and outside our tiers an off
  is the project's to make, marked in coverage as off with no reason given.
- `--duplicates`, a report beside `--unused` of functions that compute the same thing, written more than once
  (#jfvhbj7). Each function's canonical IR is hashed (TypeScript through the high-level IR, Go through the IR the
  live rules read), and functions with one digest at size 11 and up are grouped, every member named file:line.
  Functions the IR can't read faithfully are refused by name and counted, with `--verbose` listing each. A port
  kept in upstream's shape says so with a suppression naming `nexus/consistency-no-duplicate-function` or
  `cohere-go/consistency-no-duplicate-function` and its reason, and one that keeps nothing is listed. It is never
  a finding and never moves the exit code. `--json` writes `duplicate`, `duplicateRefused` and
  `duplicateCoverage` lines. A Swift project's run says its report did not run, since its engine has none.
- Go. A directory with a `go.work` or a `go.mod` is a Go project, checked by the Go engine, which is
  `cohere` itself run as a child of itself (`cohere go-engine`), so there is nothing more to install. A
  repository holding TypeScript, Swift and Go gets one report and one footer, counting each engine's
  projects, and the worst exit wins. A workspace checks every module its `go.work` uses, and a module
  no workspace uses runs on its own, with a note when a workspace above it leaves it out. A Go engine
  that crashes, prints nothing or stops early is reported as nothing checked, never as green.
- A Go file only another build compiles (another `GOOS`, cgo, a build tag) is never read green over. A plain
  run checks the machine's own build and names each such file as a gap, `⚠ 21 Go files not checked`, listed
  with its reason under `--verbose` and in `--json` as `gaps.unchecked`, and the exit is unchanged.
  `--other-builds` checks every build the project's files name beside the machine's and merges their findings,
  so only a file no build compiles stays a gap; a Swift run, a TypeScript project and a root with no Go project
  each refuse it. A run that checked more than one build says `N builds` in its footer, and `--verbose` and
  `--json` name each.
- `--timing` covers Go. A Go run under it prints what its CPU went to in the shape of TypeScript's table: each
  rule's CPU from each analyzer's own thread clock, most expensive first with its share, the intermediate
  representation's build and each dispatcher's walk as rows of their own, the load's list, parse, type-check and
  export data, and what share of the process's CPU the rows cover, the rest named as what no row measures. `--json` writes it as a `timing` line, and the run cache never replays or
  records a `--timing` run. A Swift run still refuses it.
- A root that's a Go workspace or a Swift package is format-checked too: when it holds JSON, Markdown,
  YAML or anything else the house formatter reads, outside every TypeScript project's directory, the run
  adds a `Format` project there, the format phase alone, so a misformatted file in it fails the commit gate
  as one in a TypeScript project always did. It needs no file of its own, and the summary counts it.
- An `ignorePatterns` entry says why. It's a glob, as before, or an object,
  `{ "pattern": "dist/**", "reason": "Build output.", "kind": "generated" }`, whose `kind` is `input`,
  `generated` or `thirdParty`, and whose optional `check` is `types` (see below). In a
  chain extending a `cohere:system-inc` set, and in every set cohere carries, an entry with no reason is
  refused at load, as an off with none is, and the sets' own entries each say why. `--verbose` lists every
  entry with its reason, kind, file and how many paths it matched, and `--json` carries the same, on the
  summary, or as an `ignorePatterns` record when several projects run. An entry a settings file writes that
  matches nothing is a finding, `correctness-no-unused-ignore`, which fails the run, unless its `kind` is
  `generated`, since build output may not exist yet; it's still listed, with its count of 0.
- A plain `ignorePatterns` entry means never checked at all: the type errors of the files it matches are
  dropped too, `--types` included, and they're in no count. An entry with `"check": "types"` keeps the type
  check: its files' type errors are reported, they're never linted or formatted, and the footer counts them as
  `types-only`, as `typesOnly` in `--json`. Where both match a file, the entry naming `types` wins. `--verbose`
  and `--json` also list cohere's own defaults, `testdata` (kind `input`) and `Vendor` (kind `thirdParty`), with
  their reasons. Each holds only where its tree is already skipped, by the Go engine, the format walk and the
  Swift engine, so a file a tsconfig includes under either is still type-checked and linted, and neither is
  ever an unused ignore.
- `var` is a JavaScript keyword term, not an abbreviation. `policy/KeywordTerms.json` lists the exact names in
  which a capitalized `Var` means the keyword, `VarDeclaration`, `VarDeclarations`, `VarDeclared`, `VarKeyword`
  and `VarScoped`, each read only where the name's next word starts after it, so `isVarDeclaration` and
  `TopLevelVarScopedDeclarations` read clean in every engine, while `NoVar`, `themeVar` and `VarScopedness` are
  still told to write `Variable` or say they mean the keyword. A name holding a keyword term and another
  abbreviation still reports the other. The list is decided once for every engine, and is never a project's
  `allowedSegments` entry.
- A file's name is judged as a folder's is, in every engine, by two rules each with its corpus family
  (#2xt6v5r): `consistency-no-utils-file-name` refuses `util` or `utils` as a word of the name (`util.go`,
  `stringUtils.ts`, `ViewUtil.swift`, `util_test.go`), and `consistency-no-abbreviated-file-name` judges the
  name's words by `policy/Abbreviations.json`, read as the identifier they spell (`cfg.go`, `msgPrinter.ts`).
  A word in capitals alone is an initialism or a code (`FlagCH.tsx`), and `utils` right after `no` names a ban
  on it (`consistency_no_utils_folder.go`), so neither is reported. A run of words that spells a registered
  rule's name, upstream's for a port, is the rule's and is set aside, and only the words beside it are judged:
  `max_lines.go` and `MaxClassesPerFileRule.ts` pass, `no_var_cfg.go` reports `cfg`. Only a name of two
  words or more does: `config.ts` is judged though `react-hooks/config` is registered. TypeScript reads its
  registry, Swift its own, and Go every engine's names from `docs/data/rules.json`, since a Go file in cohere is
  named for the TypeScript rule it ports.
  A name's words are cut at underscores, hyphens, dots, a Swift `+` and case, with what a tool reads set
  aside (`_test`, `_linux`, `_amd64`, `.test`, `.d`, `.config`), and a generated file, a name a tool requires
  (`doc.go`, `Package.swift`, Next.js's `page.tsx` and `next-env.d.ts`) and a file under `node_modules`,
  `vendor`, `third_party` or `testdata` are never judged. `internal/file_name_words` is the one judgment the
  TypeScript and Go rules read, and Swift ports it. Both are off in `cohere:style`, and the Go pair in cohere's
  own settings, until their census is routed.
- An editor's save of a `.go` file: `cohere --fix [--format] --stdin-filepath <path>` in a Go module or
  workspace reads the buffer on stdin and prints what a run with `--fix` would write for that file once the
  rest of the workspace type-checks, writing nothing to disk (#qtna8m4). gofmt and the long-line wrap apply;
  a rename spans files, so it is never made, and each one asked of the file is named on stderr, "left for a
  run over the module". A save loads only the file's package and what it imports, so where another package
  holds a type error, a run holds the wrap and the save makes it, ahead of the gate and never against it. An
  ignored file, one no package holds, and a buffer that does not parse come back as typed, the reason on
  stderr. The VS Code extension now formats `.go` on save.

### Changed

- `.mts` and `.cts` files are formatted, as Prettier formats them: its typescript parser with no JSX, so a
  `<T>x` cast stays a cast, and an arrow's lone type parameter keeps its `<T,>`, since upstream's `.ts` test
  misses both names. The format walk offers them, a root's `Format` project counts them, and a save through
  `--stdin-filepath` formats them, where each read them as a type no printer handles and left them as typed.
- A run that checked nothing because every file of its language was excluded fails, exit 1, where it passed with
  a warning. Its footer says how many files and why, quoting the rule that decided, as
  `no files checked: 1 file excluded, ignored by git (.gitignore:1)`, and `--json` reads `"verdict": "fail"` with
  each reason under `gaps.excluded`. A project with no file of its language at all keeps the warning and passes.
  The failure rests on the files having been there, `gaps.sourceFiles`, never on a reason having been counted: a
  file kept out for a reason cohere did not count is named as such, a cohere bug to report, and the run still fails.
- A file git tracks is never ignored, as `git check-ignore` decides it: a file added with `git add -f` under a
  pattern that matches it is checked and formatted like any other, where it read "ignored by git". cohere reads the
  repository's index itself, and a run whose index can't be read, a split or sparse one, decides by the ignore files
  alone and says so. The run cache keys the index on what it decides, the tracked paths the ignore rules exclude and
  the gitlinks, so a `git status` or a `git add` of an ordinary file still replays, and a `git add -f` doesn't.
- A project below its repository's root is formatted by the repository's ignore files and index, as `git
check-ignore` decides from there: a `.gitignore` above the project applies, and a file git tracks under a pattern
  that matches it is formatted. A walk that can't read the index, a split or sparse one, says why under `--verbose`
  and in `--json`'s `gaps.indexFallback`, since a tracked file then reads ignored.
- A git worktree reads the `info/exclude` it shares with its main checkout, as git does, where it read none: a file
  only that exclude lists is ignored, named by the file's path as `git check-ignore -v` names it.
- The footer's checked count is the files a phase examined, never the files in scope. A Swift project whose
  files had no compiler record, with lint not run, read
  `1 type error (13 checked) • ⚠ 13 files nothing checked`, and now reads no checked count beside the gap, which
  stays on the line even when a phase did not run. A replay's cached count is what the recorded run checked or
  cached, not every file in scope.
- A repository with several projects ends its default run on one footer line, the way a single project does:
  the run's time and every project's rules, checked, cached and cohered files summed. Each project's gap is on
  the line with its name, as in `⚠ 👑 lint did not run (CapturePhone)`, and a project that didn't finish or
  failed without a summary is named too. `--verbose` and `--phases` print each project's footer and the line
  counting the projects, as before, and `--json` is unchanged.
- `--directory` naming a directory that holds more than one engine's project, a `tsconfig.json` beside a `go.work`
  as Adamic's root holds them, checks each project there, as a run standing in that directory does, and reports them
  as one. It used to read the directory as TypeScript's alone and check nothing else, without saying so, and refused
  `--other-builds` as having no Go project.
- The format walk never enters `testdata`, whose fixtures are what their tests read, and the account counts
  each one it skipped.
- A declared submodule the root's `ignorePatterns` name isn't read by the nested format check, and a note
  says so.
- A failure cohere prints is one sentence: its first letter capitalized and a closing period, as in
  `cohere: No tsconfig.json, Package.swift, go.work or go.mod in /repo or any directory above it, ...`.
  A path, a file, a quoted value or another tool's output at the end keeps its spelling. A script that
  matched the old lowercase opening of a failure line should match the new one.
- The errors that name the markers cohere looks for name all four.
- `@typescript-eslint/no-redeclare` is off in `cohere:typescript` and every set that extends it. tsc reports
  every real redeclaration (TS2300, TS2451); what the rule adds is a type and a value sharing a name, which is
  valid declaration merging, as lib.es5.d.ts's own `interface Array<T>` plus `declare var Array`. A project
  that wants it turns it on in its own settings. A `no-redeclare` disable comment is now unused, and so an
  error: delete it.
- The abbreviation rule no longer guesses what `res`, `ch`, `dir`, `var` and `vars` mean. An audit of the Go
  engine's renames found `res` made `response` where it meant a result or a map's reserve size, `ch` a channel
  where it was a rune, and `dir` a directory where it was a channel's direction. Their messages now name every
  meaning, as `Use "result", "response", "resource" or "reserve", whichever it means`, and the Go engine's fix
  no longer renames them. `Var` and `Vars` can mean JavaScript's var keyword, so they say what to write for a
  variable and ask for a name saying it means the keyword otherwise. The same names are found as before. A
  local error from a call whose name holds one of the words, as `os.ReadDir`'s, is no longer named for it.
- The abbreviation rule knows the words go/ast, go/types and go/ir taught Go code. `instr`, `instrs`, `succ`,
  `succs`, `pred`, `preds`, `prog`, `alloc`, `addr`, `cond`, `conds`, `chan`, `expr`, `func`, `fset`, `stmt`,
  `ptr`, `typ`, `anon` and `deref` each name their one spelling, and `recv` (receiver or receive), `op`
  (operation, operator or operand) and `sel` (selection, selector or select) name every meaning. Each is judged
  only where its word ends, so `Condition`, `Change`, `Open`, `Function`, `Progress`, `Select` and `Type` never
  read as one. A name or file name holding one is a new finding in every engine. A whole `typ` asks Go for a
  descriptive name ending in `Type`, as `err` does, and a whole `func` asks for a name for its role, since
  `function` is reserved in TypeScript.
- A rule key in `CohereSettings.json` that names no rule cohere has, at the top level or in an override, in the
  project's own file or any file it extends, is refused at load: the run exits 1 naming the key and the file, and
  checks nothing. A typo or a rule from a newer cohere loaded, applied to nothing and read green, and only
  `--verbose` said so, as `config: key "..." matches no registered rule`, a line that is gone. `unused-disable`
  is a setting and still loads. `--format-only` reads no rules, so it is unchanged.
- A Go check leaves a workspace's go.work.sum as it was. go list in workspace mode writes every sum it reads that
  go.work.sum lacks, and drops every one a module's go.sum holds, whatever `-mod` says, so a `--no-fix` run over a
  workspace whose go.work.sum was stale rewrote a tracked file. Every go list now runs with `GOWORK` at a copy of the
  go.work outside the tree, and what go prints is spelled as it spells it from the tree, so every finding is the
  same. Where that can't be made exact, as beside a vendor directory, go list runs in the tree as before, and the
  footer says `⚠ go list may have rewritten go.work.sum`, and the file is named under `--verbose` and in `--json`'s
  `gaps.unguardedWorkspaceSums`.
- cohere's cache directory ignores itself. The run that creates `.cache/cohere` writes a `.gitignore` in it holding
  `*`, so a run in a repository whose rules say nothing of `.cache/` leaves `git status` as it found it, where a cold
  run left `.cache/` untracked. The front door, the Go engine's store and the Swift engine's scratch each write it,
  whichever creates the directory first, and never over a file that is there. A `.cache/cohere` an older cohere made
  is left as it was, and `--verbose` still says when the project's own `.gitignore` doesn't ignore it.
- Every library a run declares, a submodule or a nested repository, gets its own cohere cache at the run's start,
  where only one whose rules ignored `.cache` did, so each keeps its format record and a check formats only the
  library files that changed. The directory ignores itself, so the library's `git status` and the root's stay clean.

## 0.1.1 (2026-11-03)

No rule set changed.

### Fixed

- On a fresh clone of a Next project, 0.1.0 rewrote files to names that don't exist. With `.next/types`
  not yet generated, `PageProps` is unresolved, and the fix phase read it as the project's own name:
  `structure/react-component-require-properties-type-suffix` renamed it to `PageProperties` in 39 files
  of one project. Now, while a generated file the project imports is missing, every lint fix is held, not
  only the type-aware ones. Formatting still runs, since it reads no names. The footer says
  `⚠ 🪄 fixes held`, and `--json` carries `gaps.fixesHeld`. Run `next typegen` (or `next build`) before
  cohere in CI.
- A missing generated file reads as one cause instead of dozens of type errors. Each one prints first, at
  the import that needs it, with its remedy (`next typegen` for `.next/types`). The type errors it causes
  fold under it as one line counted by code. They still count and fail the run, and `--verbose` and
  `--json` print every one. The footer names the gap, `--json` carries `gaps.missingGenerated`, and the
  run fails even when no type error follows, so a green run never comes from a file that wasn't there. A
  missing file is one the project imports or references, that git ignores, and that isn't on disk.
- `--format-only` and `--no-format` now reach a Swift project, with the meaning they have for TypeScript,
  rather than being refused for Swift and skipping it in a mixed run.
- macOS binaries are signed with a Developer ID certificate and notarized, so a `cohere` copied or
  downloaded as a file runs rather than being killed by Gatekeeper. 0.1.0's were unsigned.

## 0.1.0 (2026-11-03)

The first release. It carries these rule sets:

- `cohere:next`, 22 rules on
- `cohere:react`, 88 rules on
- `cohere:system-inc/base`, 24 rules on
- `cohere:system-inc/structure`, 31 rules on
- `cohere:tailwind`, 12 rules on
- `cohere:typescript`, 268 rules on

Zero config: a project with no `CohereSettings.json`, or one that names no `cohere:` set, gets the house
stack, each set where the code shows it fits. `cohere:typescript` applies to every file, `cohere:react`
to each file that imports react or contains JSX, `cohere:next` to each file that imports next or is one
of Next's own files, and `cohere:tailwind` to every file when the root stylesheet imports `tailwindcss`.
package.json is never the evidence, and the run's `sets:` line names each set and why. Outside the
`cohere:system-inc/*` sets, an `"off"` needs no reason and `--coverage` names each one. Inside them,
every off and departure still says why. `nexus/import-no-forbidden-source`,
`nexus/boundary-no-nexus-outside-import` and `no-restricted-properties` (JSON.parse) moved from
`cohere:typescript` to the `cohere:system-inc/*` sets, and those sets add Buffer to
`no-restricted-globals`, since that advice names our own libraries.

Formatting: a project that configures nothing formats with the house block `cohere:typescript` carries
(tab width 4, single quotes, print width 120). A project outside the `cohere:system-inc/*` sets may set
its own `format` block in `CohereSettings.json`, applied over Prettier's defaults, so `"format": {}`
means Prettier's defaults. A project that extends a `cohere:system-inc/*` set takes its format from that
chain's Nexus tier alone, and a `format` block anywhere else in it is refused.

### Added

- Mixed repositories: a run checks the project it starts in and every project below it, each TypeScript
  program and Swift package with its own engine, in parallel, in one report whose exit code is the worst
  of theirs. Finding them never enters what `.gitignore` ignores, `node_modules`, `.build`, `.cache`,
  `testdata` or a nested repository. `--directory` or a path still narrows the run to one project.
  `--lint-config` doesn't narrow it. Each file is checked once, by the nearest tsconfig that includes
  it, and formatted once, by the project whose directory holds it. A solution tsconfig (`"files": []`
  with `references`) runs what it references, so a root that covers only config files, one with no
  tsconfig at all, and a solution root each check every project below them.
- A diagnostic about the compiler options, such as TS5102 for `baseUrl` (removed in TypeScript 7) or
  TS5023 for an option TypeScript 7 doesn't know, is reported and fails the run, but it no longer stops
  lint. Only a type error in source does. An unknown option, or an option's value of the wrong type or
  outside its values, no longer refuses the build.
- `--json` prints newline-delimited JSON for a program to read, a line per finding and per rewritten file
  and a summary last, described by `schema/CohereOutput.schema.json`.

### Changed

- A bare `cohere` formats too: it type-checks, lints, applies fixes and formats in one call. `--fix`
  applies fixes and formats, running no other phase, and `--no-fix` reports what formatting would change
  beside what fixing would, and exits nonzero on either. `--no-format` leaves formatting out of all three.
  `--format` keeps its meaning and changes nothing on those runs, since they already format.
- The default output: a run prints the files it rewrote, its findings as `path:line:col severity rule
message`, and one footer line, `✓ 💎 0.7s • 2 cohered (480 rules • 3 checked • 3,923 cached)`, whose
  counts are exact and which names anything the run did not check even when it passes. `--verbose`
  prints everything a run printed before, notes included, and `--phases` (or
  `"output": { "phases": true }` in `CohereSettings.json`) adds the phase timings to the footer. Exit
  codes are unchanged.
- `getter-return` checks TypeScript files, as ESLint does where a config turns it on there. It used to
  skip every `.ts` and `.tsx` file. It also reports what ESLint reports: a bare `return;` at the
  statement (`expected`), and a getter that falls off the end at its head, from the property to the
  parameters' opening paren (`expectedAlways` when it returns on another path). `no-setter-return` now
  reports a setter declared through a property descriptor (`Object.defineProperty`,
  `Object.defineProperties`, `Object.create`, `Reflect.defineProperty`). Both rules count a descriptor
  only where its method reads one, and only when `Object` or `Reflect` is the global.
- `preserve-caught-error` matches ESLint on cause selection and keys. The last `cause` key is the one
  read, as it is at runtime, and a quoted, template or bracketed-literal key named `cause` counts. A
  wrong cause reports at its value (`incorrectCause`), a destructured catch parameter at the catch
  clause (`partiallyLostError`), a cause shadowed by a closer declaration at the throw
  (`caughtErrorShadowed`), and `requireCatchParameter` at each throw rather than at the clause
  (`missingCatchErrorParam`); the uncaused throw is `missingCause`. All eight built-in error types
  count, `errorClassNames` names more, a throw inside an arrow function or static block is no longer
  examined, parentheses are read through, and options that are not an object literal are left alone.
  The repair is a suggestion now, not a fix, since attaching a cause changes what the error carries.
- `no-obj-calls` matches ESLint. `Temporal` counts, and a call reaches the namespace object however
  ESLint's reference tracker would follow it: through a name it was copied into, a default value, an
  object pattern, a conditional or logical expression, a comma, parentheses, a type assertion, or a
  global object with a constant computed key (`globalThis["JSON"]`). A local named `globalThis` is not
  taken for the global, and a file that writes to a global is not checked for it. The ids are ESLint's:
  `unexpectedCall`, and `unexpectedRefCall` when the callee is another name.
- `no-implicit-globals` reports an assignment to an undeclared name only in sloppy code. In strict code
  that assignment throws instead of creating a global, and a module is strict, as is every TypeScript
  file under `alwaysStrict`, so in a TypeScript program the leak is reported only in a JavaScript
  script. A script's top-level `var` or function declaration still reports, strict or not, since it is
  a global either way.
- `prefer-const` reports where ESLint does. A `let` with no initializer is reported at its one write,
  the line that would become the declaration, or at the declaration when something reads it before that
  write. A destructuring assignment can be that write now (`let a; ({a} = obj);`), when every target in
  its pattern is a plain name either undeclared or a `let` beside it, and under `"all"` the names one
  assignment writes report together or not at all. A write that is only part of its statement, such as
  `foo() || (x = 0)` or `y = x = 0`, is no longer taken for one that initializes, and under
  `ignoreReadBeforeAssign` the declaration's own name no longer counts as a read, so `let x; x = 0;`
  reports there too.
- `no-useless-backreference` reports where ESLint does and with its ids (`nested`, `disjunctive`,
  `forward`, `backward`, `intoNegativeLookaround`): at the whole regex literal, or the whole `RegExp`
  call, rather than at the backreference, which the message names. A call is found as ESLint's reference
  tracker finds it, so a local named `RegExp` is not the global, and an alias or `globalThis.RegExp` is.
  The pattern and flags are read as constants are, a `const` or never-written binding's value included,
  and flags that cannot be read count as none. Every regex literal is checked under its own flags, one
  passed to `RegExp` too. A named reference to a duplicated group reports only when every group of that
  name is out of its reach.
- `no-misleading-character-class` finds `RegExp` calls as ESLint's reference tracker does, so a local
  named `RegExp` is not the global, and an alias or `globalThis.RegExp` is. A pattern or flags held in a
  `const` or never-written binding, or built by concatenation, is read. A pattern that reached the call
  that way reports once per kind at the argument, and a string or template still reports at the
  characters. A pattern whose value is a RegExp object is not read, and flags that cannot be read still
  decline the call. Its message ids are ESLint's: `surrogatePair`, `surrogatePairWithoutUFlag`,
  `combiningClass`, `emojiModifier`, `regionalIndicatorSymbol` and `zwj`, and the suggestion's is
  `suggestUnicodeFlag`.
- `prefer-regex-literals` finds `RegExp` calls as ESLint's reference tracker does: through an alias
  (`const R = RegExp`), a parenthesized callee, a pattern destructured from `globalThis`, and `window`,
  which an undeclared name makes the runtime's global object. A local named `RegExp` is still not it.
- `prefer-object-spread` finds `Object.assign` calls as ESLint's reference tracker does: through a
  destructured, renamed or copied `Object` (`const { assign } = Object; assign({}, a)`), a parenthesized
  callee, and an optional call either way (`Object?.assign`, `Object.assign?.()`), which it now reports
  and fixes, since `Object` is never nullish. A file that writes `Object` is still not followed.
